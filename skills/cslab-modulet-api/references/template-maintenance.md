# moduleT 变量配置、骨架与写接口

## 新增契约变量

当前模板、项目 Skill 和后台变量目录都未约定的新模块契约变量，必须先形成配置清单并由
开发者确认。契约变量包括构造注入、模板输入/输出、需展示或落库的实例属性、配置状态、
初边值和连接节点；方法局部量、中间量、循环变量及私有缓存不配置到后台。

属性清单至少说明：

- `name` 与构造形参/实例属性的同名关系；
- 中文简称、完整含义和作用；
- `classify`、`classify2`、默认值及 SI 口径；
- `unitType`、`unit`、`opt_unit`；
- 标量/向量/矩阵 shape、组分坐标和有效范围；
- `is_input`、数据来源和真实输出消费者；
- 目标模板、枚举源、联动、显示条件和状态规则。

节点还要说明 `code`、`interface`、`phase`、是否允许未连接、注入形参和上下游语义。

配置流程：先读详情、Skill 和变量目录确认确实缺失；完整展示方案；开发者确认后自行配置
或明确授权 Agent；写入后再次读取详情逐字段核对；只有复核通过才能写入已确认变量目录并
用于编码。禁止用 `**kwargs`、硬编码或运行时临时属性绕过配置。

## pyTemp

`GET moduleT/pyTemp?pk=<id>&class_name=<类名>` 根据模板属性和节点生成类骨架。它只作为
起点：默认值渲染为 `None`，缺少 `Data`/`Method_bag`、业务基类和实际 `Run` 逻辑，仍须
按通用契约与族 Skill 补全。

已知边界：

- 数值属性默认值为 NULL 时，服务端执行 `int/float(None)` 可返回 500；重试无效。读取
  模板详情手工生成形参，并把空默认值属性报告开发者。
- `class_name` 缺失或非法、pk 不存在、属性与节点重名可能产生不可用骨架；取得后先用
  `ast.parse` 做语法检查。

## 写接口

POST/PUT/DELETE `moduleT/` 的 body：

```json
{"item": "moduleT" | "modulePropT" | "moduleNodeT", "parameter": {}}
```

- 模板、属性和节点有各自字段白名单。PUT 含白名单外字段时可能整体拒绝；POST 的多余
  字段可能被忽略，不能把 HTTP 成功当作字段已落库。
- 系统模板通常需要管理员；普通账号受个人模板、分类和名称前缀限制。
- 修改属性或节点会直接改变参数注入契约，必须先确认算法形参、实例属性和测试是否联动。
- 写前确认 `isOperator`、目标 id、完整 payload 和开发者授权；写后必须重新读取详情复核。
