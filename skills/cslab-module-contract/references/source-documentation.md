# CSLab 源码文档与最小实现

## 中文文档规范

1. 模块说明、类说明、方法 docstring 和解释性注释统一使用简体中文；变量名、接口名、
   单位、数学符号和第三方专有名词保留原文。
2. 文件顶部在 import 前放模块级 docstring，说明文件用途、适用范围、核心方程、求解或
   离散方法、调度入口、关键单位和已确认假设。动态模块还要列出状态微分方程及积分方法。
3. 每个方法均有中文 docstring，包括 `__init__`、私有方法、`staticmethod`、
   `classmethod` 和 `property`。
4. docstring 按实际复杂度说明：目的；每个参数的含义、类型、单位、shape、坐标和来源；
   返回；修改的实例状态或出口；异常/保护行为；主要执行步骤。
5. 每条主要方程标明衡算类型和对象，并解释变量意义、单位、维度、正负号、来源、初始
   条件、边界条件、闭合关系和求解方法。
6. 模型假设只记录开发者已确认的选择，说明适用范围和影响；外部模型记录资料来源。
7. 主入口按真实顺序说明先算什么、依赖什么、修改什么，并指出温度、压力、组成和流量是
   输入、固定值、继承值还是求解结果。

简单且无参数、返回和副作用的方法可以简短说明；复杂热路径或动态积分方法在 docstring
之外使用项目规定的步骤式中文注释，解释物理口径、索引、状态提交和回退原因，不逐行复述。

## 最小必要实现

每个方法、参数、内部状态、缓存、返回值和结果字段至少对应以下一项：

1. 当前模板、调度器或公开调用契约；
2. 开发者确认的方程、数值方法或边界保护；
3. 已核实的前端、落库、下游节点或调用方消费者；
4. 明确的异常隔离、复用、性能或独立测试价值。

不能对应时删除或内联。只包装显而易见表达式、没有复用和独立失败语义的辅助方法通常
内联；只写未读的私有状态、未使用的普通参数和重复同步删除。模板同名形参、框架反射入口
和入口兼容形参即使算法体内未读取，也属于契约代码，应在 docstring 说明消费者和保留原因。

## 源码审计

使用本 Skill 自带脚本预检目标 `.py`：

```powershell
uv run python .agents/skills/cslab-module-contract/scripts/audit_module_source.py `
  --family generic <目标.py>
```

脚本检查语法、中文文档、`print` 调试残留、明显无消费者的私有方法和状态。它不能证明
模板反射、外部消费者、物理必要性或注释语义；警告不能单独作为删除代码的依据。

## 交付检查

- 模块、类和全部方法的中文文档与实际签名一致。
- 方程、变量、单位、shape、状态副作用和保护行为均可由文档理解。
- 主入口的计算顺序和关键状态来源明确。
- 每个保留元素都有可验证用途；临时观测和无消费者结构已删除。
- 只交付 `.py`，并由真实入口加载验证。
