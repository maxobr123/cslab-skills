# 动态模块专项验证

通用源码直载、单模块和整图步骤以 `cslab-module-verify` 为准，本文只补充动态验收。

1. 只隔离目标模块同名 `.pyd/.so`，保留其他编译依赖，不读取目标二进制。
2. 使用 `python -B` 加载目标 `.py`，确认 `module.__file__` 指向本地源码。
3. 从当前项目实际入口运行，不用网页结果证明本地代码；记录控制器映射、主/子进程角色、
   模板 `startFun` 和预期设备入口。
4. V4 子进程要证明控制器 `run()` 实际调用设备 `RunDynamic()`；普通主进程证明模板入口
   被调用，不能只观察进程无错误。
5. 记录工程 `Data.PGV["DT"]` 的实际值，连续采样多个时间步，验证每次只推进一个 DT、
   状态方向符合方程、守恒残差满足容差、出口被下游采用。
6. 至少覆盖静止、正常变化、干/满或其他确认边界、无效 DT、候选失败和出口发布失败。
7. 验证状态、同名实例属性和出口处于同一时间层级；无消费者时入口没有无用结果结构。
8. 只停止本次启动的进程；删除临时观测代码后执行最终回归。

源码审计使用：

```powershell
uv run python .agents/skills/cslab-module-contract/scripts/audit_module_source.py `
  --family generic <目标.py>
```

审计不能替代动态时间序列、入口调用和守恒验证。
