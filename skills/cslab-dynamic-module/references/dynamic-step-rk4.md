# 动态单步、RK4 与状态发布

## 编码前公开设计

向开发者说明：控制器和入口；每个状态的初值、导数、边界和回写位置；温度、压力、组成、
流量等是固定输入、上游边界、代数结果还是动态状态；DT 与事件子步关系；上下游采用本步
还是下一步边界；空/满设备、相态切换、不收敛和断开节点的处理。

每条方程说明衡算类型和对象、完整公式、全部变量的意义/单位/shape/正负号/来源、初边值、
闭合关系、已确认假设和数值方法。开发者未确认时停在设计阶段。

## 一次入口、一次推进

- 普通 V4 主进程 `Run()`、子进程 `RunDynamic()` 或特殊 `RunOde(ts, dt)` 各自承担完整
  单步职责，不能在另一入口重复积分。
- 推荐把入口调度与状态积分分成 `_advance_one_step` 和 `_rk4_step`；已有等价方法可保留
  历史名称，但 docstring 必须标明职责。
- 入口快照边界和旧状态，计算候选，执行保护，发布出口，最后提交内部状态。
- RK4 函数是纯候选计算，不写模板属性、缓存或真实出口。

## 经典 RK4

设 `h=DT`、`dy/dt=f(t,y,boundary)`：

```text
k1 = f(t_n,         y_n,             boundary)
k2 = f(t_n + h/2,   y_n + h*k1/2,    boundary)
k3 = f(t_n + h/2,   y_n + h*k2/2,    boundary)
k4 = f(t_n + h,     y_n + h*k3,      boundary)
y_(n+1) = y_n + h*(k1 + 2*k2 + 2*k3 + k4)/6
```

明确 boundary 在四阶段是冻结、阶段重算还是外部插值，不混用时间层级。每个 k 的 shape 和
单位与状态向量一致；中间状态可保护，但只有步末候选能提交。

步内触满、耗尽、相态切换等事件先定位，再对事件前后分别执行 RK4 子步，子步时长之和必须
严格等于 DT。没有解析依据时不能用一次步末截断代替事件守恒。

只有刚性、DAE、强不连续、已确认解析更新或 RK4 经验证不满足稳定性/性能时才改方法。
改变默认方法属于结果风险，须比较精度、稳定性、步长和性能并由开发者确认。纯代数后处理
或精确解析更新可以不调用 RK4，但仍保留单步职责并说明依据。

## 动态保护与原子提交

通用保护使用 `cslab-module-contract/references/numerical-boundary-protection.md`。动态另要求：

1. 同一步的流量、密度、温度、组成和物性明确时间层级。
2. 容差、投影、备用计算和上一值都来自确认的保护表，不把所有异常值置零。
3. 干槽、满槽、溢流、停机等是正常边界，不发送错误反馈。
4. 修正后仍满足质量、组分和能量衡算；截断量必须有物理去向。
5. 候选无法恢复时跳过该步；出口发布失败时恢复出口快照并保留旧状态。

## 输出、诊断与最小实现

普通 V4 动态设备通常以同名实例属性供展示/落库，以出口节点供下游。没有返回消费者时不
定义 `result`、`result_fail` 或成功二元组。每步集中同步，避免消费者看到不同时刻的数据。

临时观测使用 logger 或测试入口外部采集，记录时间、实际入口、DT、关键状态、流入、流出
和残差；验证后删除。辅助方法必须有独立状态、边界或诊断职责；常量导数的一次包装、重复
同步和未读取状态删除或内联。
