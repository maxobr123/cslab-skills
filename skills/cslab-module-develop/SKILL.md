# CSLab 工程算法开发入口

本 Skill 负责“能否开始编码”的开发流程，不重复定义平台运行契约、模板 API、测试脚手架
或设备族算法。适用于 operation、dynamic、control、design、chemical-principle、
property-method 等所有 CSLab 工程算法任务。

## 强制流程

```text
风险分级 → 需求事实与测试契约 → 模板/调用方/消费者取证
→ 开发者资料询问与联网调研 → 全部候选方案和模型假设选择
→ 公开计算设计 → 开发者最终确认 → 仅修改.py
→ 源码直载与业务验证 → 交付记录
```

出现以下任一情况必须停在编码前等待：测试契约不完整；A 级任务尚未回答资料询问；关键
方案、模型假设或数值方法未明确选择；完整技术方案未得到“完全理解并同意实施”的明确
确认；新增后台契约变量尚未配置并经模板详情 API 复核。

## 风险分级

| 等级 | 判定 | 必须完成 |
|---|---|---|
| A 结果风险 | 改变方程、假设、数值方法、边界、相态、单位口径或计算结果 | 资料询问、联网调研、全部候选比较、假设选择、公开计算设计和最终确认 |
| B 契约风险 | 改变构造参数、模板属性/节点、`startFun`、消费者、返回或错误传播 | 核实模板/API/控制器，展示契约差异、影响与测试；影响结果时升级为 A |
| C 行为保持 | 只补注释、删除已证明无消费者的死代码、内联冗余包装或整理格式 | 给出行为不变证据、删除依据和回归测试；不虚构物理方案 |

无法证明行为不变时按更高等级处理。任何等级修改算法 `.py` 前，都必须展示范围、目标
文件、消费者、风险和测试契约并取得明确实施确认。

## 开发文件边界

- 只有目标算法 `.py` 是开发源码、审查对象和交付物。
- `.pyd`、`.so`、`.pyc` 是运行依赖或产物，不是开发文件、参考实现或完成证明；不得
  读取、反编译、反射、试探或修改其内部实现。
- 只有同名二进制而没有 `.py` 时，依据模板、公开契约、项目 Skill 和已确认设计新建
  `.py`，不得还原二进制源码。
- 算法开发任务不编译、生成、修改或交付 `.pyd`；二进制发布必须由开发者另行发起。
- 验证时可按 `cslab-module-verify` 临时隔离目标同名二进制，但该操作不计入开发改动。

## 最短执行规则

### 1. 建立需求与测试契约

先记录目标文件和类、计算模式与设备族、输入/输出/端口、状态与初边值、单位、消费者、
禁止修改范围、精度/性能要求。信息分为“已确认事实、待确认、暂定推测”；提示词已明确
的事项不重复询问，会改变模型或接口的缺口必须确认。

编码前必须明确实际测试位置、测试类型、数据来源、执行对象、输入工况和可观测验收标准。
CSLab 项目计算需确认 `pro`；单独物性计算还需确认 `Method_bag`；验收必须确认实际导入
本次 `.py`。不得复用历史示例编号，也不得假定某个测试文件在其他开发者仓库存在。

需要建立完整事实表和测试契约表时，读取
[references/requirements-and-test-contract.md](references/requirements-and-test-contract.md)。
实际测试入口发现与脚手架由 `cslab-module-verify` 定义。

### 2. 核实模板和公开契约

- 模板驱动模块加载 `cslab-modulet-api`，查询当前模板详情、算法槽位、`startFun`、属性、
  节点和后台变量；没有模板的底层算法从公开调用方与所属 Skill 取证。
- 编码前加载 `cslab-module-contract`，核对构造注入、入口、消费者驱动输出、feedback、
  中文源码文档、通用数值保护和最小必要实现。
- 按所属族加载对应 Skill：稳态通用单元用 `cslab-operation-unit-skeleton`；FlashTank 用
  `cslab-operation-flashtank`；动态用 `cslab-dynamic-module`；实际调用 Flash 或物性时
  分别加载 `cslab-operation-flash`、`cslab-operation-phy-prop`。
- 没有适用族 Skill 时明确告知开发者，依据真实模板和调用方工作，不套用其他族规则。

本 Skill 不复制上述 Skill 已拥有的接口和步骤；需要操作时必须读取其当前版本。

### 3. 新后台变量门禁

若开发需要增加当前模板、项目 Skill 和后台变量目录均未约定的构造注入参数、模板输入/
输出、可配置状态、初边值、需展示或落库的实例属性、连接节点，必须提醒开发者先在后台
配置。逐项说明变量名、类型、含义、作用、单位、shape、方向、默认值、范围、来源和模板
范围；节点还要说明类型、方向、相态、未连接语义和上下游作用。

按 `cslab-modulet-api` 完成配置与模板详情 API 复核后才能编码。只有开发者明确授权目标
模板、载荷和写权限时，Agent 才能代为写入。API 未返回或字段不一致时停止；不得使用
`**kwargs`、硬编码默认值、临时实例属性或只改 `.py` 绕过。方法局部量和私有缓存无需后台
配置，但须在方程变量表或方法注释中说明。无模板底层算法以其公开调用契约为准。

### 4. 开发者资料与联网调研门禁

A 级任务在联网前先询问开发者是否能提供 PDF、网页、标准、论文、教材、设计手册、设备
资料、工艺包、公式、流程图、测试数据或参考结果，并说明不确定是否有用的资料也可先交由
Agent 分析。开发者给出资料时先分析再联网补充；明确表示没有资料后方可继续；尚未回答
时必须等待。

联网调研须使用可核查的标准、教材、论文、官方文档或可靠工程资料，记录标题、链接、
访问日期、适用对象和条件。不得把搜索摘要或目标二进制当作模型依据。没有可靠来源时
报告阻塞并索取依据，不凭记忆补造。B/C 级只有发现结果口径改变时才升级执行本门禁。

完整调研、候选比较、方程表和评审记录格式见
[references/research-and-design-review.md](references/research-and-design-review.md)。

### 5. 全部候选和模型假设选择门禁

先完整展示所有候选方案的依据、适用条件、衡算、状态、闭合、数值方法、精度、性能和
限制，再给出有依据的推荐；候选数量不限，不能因控件限制删减、合并、代选。所有会改变
结果的模型假设、数值方法、边界与回退必须分别由开发者确认。

- `request_user_input` 可用且当前问题有 2 至 3 个互斥项时使用原生列表；推荐项排第一并
  标“（推荐）”，说明影响与取舍。
- 超过三个候选时，按物理上有意义的模型家族、闭合方式或数值方法分组，通过多轮原生
  列表逐层选择；分组不能丢弃任何候选，也不能由 Agent 筛选代替开发者选择。
- 独立假设分别提问，每个问题 2 至 3 个互斥项，每轮最多三个问题；未确认项留待下轮。
- 不设置自动超时、默认继续或默认选择；推荐项、沉默和未反对都不是确认。
- 提示词已明确指定的选择记录为“已确认设计”，不重复询问，只补实质缺口。
- 原生列表不可用时，给出等价编号列表并等待明确回复；权限授权框不能承载业务选择。

### 6. 公开计算设计与最终确认

编码前完整说明主入口的计算顺序：每步计算什么、依赖什么、修改什么状态、写入哪个已
确认消费者。列出每项衡算的系统边界和类型、完整方程、所有变量的意义/单位/维度/符号/
来源、初边值与闭合关系、求解方法及数值保护。数值保护细节加载
`cslab-module-contract`；改变投影、回退、守恒去向或结果时按 A 级重新选择。

随后完整展示目标与边界、来源与全部候选、已选假设、计算顺序和方程、接口与消费者、
数值方法与保护、后台变量、拟改 `.py`、测试、风险、限制和性能影响。明确提示开发者可
继续询问，并要求在以下三项中明确选择；`request_user_input` 可用时使用原生列表，不可用
时使用等价编号列表并等待回复：

1. 有不明白，需要继续解释；
2. 完全理解并同意实施；
3. 不同意，需要调整方案。

继续解释后必须重新展示完整当前方案；调整方案则返回调研和设计阶段。方案、假设、方程、
接口或数值方法实质变化后旧确认失效。只有“完全理解并同意实施”或语义完全等价的明确
回复才能进入编码；“大概可以”“先试试”、推荐项、默认项、沉默或超时均不构成确认。

### 7. 实现、验证和交付

只实现已确认方案；出现新推测、结果口径变化或未约定后台变量时立即退回对应门禁。
实现细节完全遵守 `cslab-module-contract` 和所属族 Skill，不保留没有契约、物理、消费者、
异常隔离、复用或测试依据的方法、状态和结果字段；所有源码说明使用中文。

实现后加载 `cslab-module-verify`，在 Python 3.7.6 下按实际入口验证，并证明
`module.__file__` 指向目标 `.py`。网页服务器结果不能替代本地源码验收。交付只列 `.py`，
同时记录已选设计、模板变更、消费者、真实验证、未覆盖范围和风险；模板槽位或后台变量
登记按 `cslab-modulet-api` 执行。

## 完成判定

只有测试契约成立、所有适用门禁通过、目标 `.py` 被实际加载、验收标准得到证据且遗留
风险如实记录，才能宣称完成。无法运行时明确标注“未运行验证”、原因和剩余风险。
