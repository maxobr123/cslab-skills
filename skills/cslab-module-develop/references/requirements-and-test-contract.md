# 需求事实与测试契约

仅在需要建立开发记录或测试契约时读取。测试命令和脚手架由 `cslab-module-verify` 定义。

## 需求事实表

| 项目 | 需要记录的事实 |
|---|---|
| 任务 | 新建、修改或修复；目标 `.py`、类和算法槽位 |
| 归属 | 计算模式、设备族、模板或公开调用方 |
| 计算边界 | 输入、输出、端口、状态、初始条件、边界条件和闭合关系 |
| 单位与坐标 | 每个量的单位、shape、组分坐标和正负号 |
| 消费者 | 入口返回、`result`、同名实例属性、出口节点或其他调用方 |
| 质量目标 | 精度、性能、稳定性、兼容性及禁止修改范围 |
| 不确定性 | 已确认事实、待开发者确认和暂定推测 |

没有真实消费者的输出通道记录为“不适用”，不生成结果、实例属性或出口占位。建立变量
表时读取 `cslab-operation-unit-skeleton/references/operation-variables.md` 的权威词汇和
Flow 扩展规则；设备专用字段仍受其适用范围限制。词汇表中的候选名不能证明当前模板
已配置，模板事实以当前详情 API 为准。

## 测试契约表

| 项目 | 必须确认的内容 |
|---|---|
| 测试类型 | 单独物性、单模块、完整本地工程、动态联调或其他 |
| 实际测试位置 | 开发者指定，或在当前项目检索、读取并确认的真实路径 |
| 数据工程 | CSLab 取数和项目计算使用的 `pro` |
| 方法包 | 单独物性测试所需 `Method_bag` |
| 执行对象 | 具体物性对象、模块类或项目控制器 |
| 输入工况 | 属性、温压、组成、流量、时间范围或其他必要输入 |
| 验收标准 | 参考值、误差、衡算闭合、时间变化、消费者或其他可观测结果 |
| 环境依赖 | 服务、Python 3.7.6 和必要的兼容二进制依赖 |
| 源码证据 | `module.__file__` 必须指向本次目标 `.py` |

## 测试形式边界

- 单独物性测试通过 `pro + Method_bag` 请求 `chemicalData`，调用
  `instantiation_data(...)` 构造 `Data`，实例化合适的公开物性对象，再调用统一标量或
  矩阵物性接口。这里约定形式，不约定测试脚本目录或文件名。
- 完整项目计算使用当前项目真实存在的运行入口。优先采用开发者指定路径；未指定时检索
  候选，读取其数据加载、控制器和启动签名后再确认。记录 `pro`、计算模式及入口需要的
  `pk`、`special_pk`、服务地址等参数。
- 缺少必要 `pro`、物性测试所需 `Method_bag`、实际入口或验收标准时保持待确认，不用
  历史示例值代替。

## 模板证据摘要

模板驱动模块须从当前模板详情记录：算法槽位和类、`startFun`、所有属性和节点、类型、
单位、默认值、输入输出方向、未连接节点语义及输出消费者。模板注入和 API 操作细节必须
读取 `cslab-modulet-api`，不要在本记录中复制一套接口规则。
