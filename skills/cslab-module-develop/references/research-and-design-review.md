# 技术调研与设计评审记录

仅在 A 级结果风险任务，或 B/C 级实施中发现结果口径变化时读取。

## 资料分析与联网调研

开发者提供资料后，先提取适用对象、工况、方程、变量、单位、假设、限制和验证数据，再
用可靠网络资料补充或交叉验证。资料冲突时完整展示差异并交由开发者选择，不能自行拼接。

每项网络资料记录：

| 项目 | 内容 |
|---|---|
| 来源 | 标题、作者或发布机构、链接、访问日期 |
| 适用性 | 设备或过程、工况、体系、假设和限制 |
| 计算口径 | 衡算类型、状态变量、闭合关系和主要方程 |
| 数值实现 | 求解或积分方法、初值、容差、稳定性和性能 |
| 验证依据 | 实验、算例、标准范围或其他可核查结果 |

调研必须覆盖全部实质可行方案。来源之间不一致时记录差异；网络不可用或没有可靠依据时，
停止并向开发者索取资料或允许采用的依据。

## 候选方案比较

| 项目 | 每个候选都要说明 |
|---|---|
| 模型 | 物理/经验模型、系统边界和衡算对象 |
| 状态与闭合 | 状态变量、方程数、闭合关系、初边值 |
| 假设 | 理想性、相态、混合、热边界、物性和适用范围 |
| 数值方法 | 求解器或积分器、步长、初值、容差、收敛和回退 |
| 工程影响 | 精度、复杂度、性能、数据需求、限制和未覆盖场景 |
| 推荐依据 | 可核查来源以及与当前测试契约的匹配程度 |

先展示完整对比，再按主 Skill 的原生列表或编号回退规则让开发者选择。独立模型假设分别
确认，不把推荐项当成授权。

## 公开计算设计

对每个主入口按顺序说明：读取哪些输入；先算什么；调用哪些公开能力；如何迭代、积分或
收敛；何时进行数值保护；何时提交状态；向哪些已确认消费者写值。没有消费者的通道明确
标记“不适用”。

每条主要方程使用下表：

| 项目 | 内容 |
|---|---|
| 方程名称 | 总质量、组分、能量、动量、相平衡、经验关联式或其他类型 |
| 衡算对象 | 系统边界及被衡算的物质、组分、能量或动量 |
| 公式 | 完整数学表达式 |
| 变量表 | 每个变量的意义、单位、维度、正负号和数据来源 |
| 条件 | 初始条件、边界条件、闭合关系、适用范围和已确认假设 |
| 求解 | 解析、迭代、优化或时间积分方法，以及容差和步长 |

涉及可恢复数值边界时读取
`cslab-module-contract/references/numerical-boundary-protection.md`，并记录：

| 项目 | 内容 |
|---|---|
| 保护对象 | 输入、中间量、求解结果、矩阵 case、状态或出口对象 |
| 合法边界 | 类型、shape、单位、上下限和边界等号的物理意义 |
| 容差 | `atol/rtol`、单位、依据和适用关系 |
| 保护动作 | 投影、归零、归一化、备用计算、上一有效值、跳过本步或回滚 |
| 守恒与状态 | 修正量的守恒去向、旧状态范围及输出影响 |
| 验证工况 | 正常、边界、容差内外、局部失败和恢复后的预期结果 |

保护只处理可恢复数值边界，不抛异常或发送错误反馈。保护改变结果、回退顺序、投影或
守恒去向时属于 A 级决策，必须重新选择和确认。

## 最终评审清单

最终确认前完整展示：

1. 开发目标、系统边界、覆盖和不覆盖范围；
2. 调研来源、全部候选、对比、已选方案和理由；
3. 全部模型假设、入口与方法计算顺序；
4. 衡算对象、主要方程和完整变量说明；
5. 输入、状态、输出及每个消费者，不适用通道的原因；
6. 数值方法、初值、步长、容差、收敛、保护、回退和状态保留；
7. 待配置后台变量、拟改 `.py`、测试契约、风险、限制和性能影响。

开发者选择继续解释后，答疑并重新展示完整方案；选择调整则更新调研与设计。只有明确
选择“完全理解并同意实施”后记录带版本的已确认设计，方案发生实质变化时该版本失效。
